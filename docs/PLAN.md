# 租房搜索 Skill 实施计划

日期：2026-10-03。目标：用户描述地区、预算、设施和朝向，由 Codex / WorkBuddy 的联网工具找候选房源，生成有原始链接和证据的对比结果。先服务江浙沪，再推广全国。

## 方案与范围

采用标准 Agent Skill + 宿主搜索/浏览器 + Python 3.10+ 标准库辅助程序。相比纯提示词，脚本保证预算计算、硬条件筛选和重复链接处理一致；相比每站专用爬虫，减少登录、页面变化和维护成本。脚本不负责联网，AI 按 Skill 逐站搜索和打开详情，不能把生成搜索链接当作已完成找房。

同一 Skill 源码生成 Codex 和 WorkBuddy 包。城市目录覆盖江浙沪 25 个地级行政区；上海、杭州、南京、苏州、宁波、无锡优先验收，其他城市及全国使用城市名加站点搜索，不能宣称完整覆盖库存。默认来源为贝壳、自如、58，链家、安居客、我爱我家、豆瓣、小红书可按访问能力补充；贝壳/链家和58/安居客分别算同一来源组。

初版采用 MIT、rental-finder-cn，先交付本地源码和安装包。后续经维护者授权，将源码发布到 yhzll99/rental-hunter-skill；见 [发布记录](RELEASE.md)。

## 数据约定

需求分 hard / preferences；预算包含金额及口径 rent / fixed_total / total_monthly。事实统一记录 value + evidence；缺少事实不得推断为否或零。每条结果记录 URL、平台、读取时间、证据层级；摘要只做线索。程序返回 meets_documented / needs_verification / excluded，第一种仅代表页面记载符合，不保证当前仍可租。

## 验收与文件职责

- tests/test_core.py：真实用户会遇到的预算、证据、重复和查询边界；unittest discover 通过。
- tests/test_distribution.py：两种 ZIP 的入口、安装冲突和无隐式覆盖。
- skills/rental-finder-cn/SKILL.md：联网行动、条件解析、证据和结果交付。
- skills/rental-finder-cn/references/：城市与来源目录、字段规范。
- examples/：明确标注模拟的需求与候选输入，可重复运行。
- docs/VALIDATION.md：区分本地通过、在线抽测和 WorkBuddy 未实机验证。

重点审阅：搜索摘要冒充详情；未知费用当零；“南北”自动当“朝南”；过期页面当可租；同 URL 的不同房间/冲突数据误合并。每项都应有程序测试或行为场景。

## 执行决策

- 使用当前空工作目录中的独立项目目录，不额外创建工作树；没有既存代码需要隔离。
- 核心流程用宿主工具实际检索，未实现站点私有 API 或浏览器 DOM 选择器，代价是实时访问取决于宿主。
- 保留完整 JSON 供审计，Markdown 作为候选中间报告，由 AI 完成最终搜索记录和结论。
- 首版日期、复杂通勤等采用人工证据核验，不伪装成全部字段均自动判断。
- 创建双宿主包但 WorkBuddy 只校验包格式，实机导入留作发布前验收。
